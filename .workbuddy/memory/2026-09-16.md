## 8. MCP 导入 404（13:00-13:20，框架级缺口修复）
- 现象：前端 `/mcp` 点导入，`POST http://localhost:5173/api/mcp/import`（Vite 代理 → https://localhost:7242）返回 404。
- 排查：后端在跑；`/openapi/v1.json` **包含**全部 5 个 `/api/mcp/*` 路由；但直接打后端 `POST /api/mcp/import` 404、`POST /api/mcp/servers`（GET-only）也 404（非 405）、无鉴权 404（非 401）；对照 `POST /api/identity/login` 空 body 返回 400（正常）。→ 路由**根本没映射**，404 来自无匹配路由。
- 根因：MCP 是第一个用 MVC `[ApiController]` 的模块。`AddModules`（ModuleExtensions.cs）只 `AddMvcCore()` + `AddApplicationPart(asm)`——这让控制器进了 OpenAPI（ApiDescription 只看程序集，不管路由），但 `MapModuleEndpoints()` 从不调用 `MapControllers()` → MVC 路由不进路由表。全仓库 grep 无任何 `MapControllers`。
- 修复（框架层，保持"新模块零改 Host"）：
  1. `ModuleExtensions.MapModuleEndpoints()` 增加 `endpoints.MapControllers()`；
  2. 新增 `Nova.Framework.Authorization/RequirePermissionActionFilter.cs`（IAsyncAuthorizationFilter）：MVC Controller 的 `[RequirePermission]` 此前**无人执行**（PermissionFilter 是 IEndpointFilter，只挂声明式端点）→ 全局挂载，类级+方法级 AND、401/403 语义与 PermissionFilter 一致（IPermissionChecker 优先，降级走 Permission claims + PermissionMatcher）；
  3. `AddModules` 里 `mvcBuilder.AddMvcOptions(o => o.Filters.Add<RequirePermissionActionFilter>())`。
- 可行性已核实：ASP.NET Core 源码确认 `AddMvcCore()` 注册 `ControllerActionEndpointDataSourceFactory`/JSON 输入输出格式化器（`[FromBody]` 不会 415）；`Nova.Framework.Web.csproj` 已引用 `Nova.Framework.Authorization`；`Program.cs:61` 有 `UseAuthorization()`，Controller 的 `[Authorize]` 可用。
- 用户需在 VS 重新编译+重启后端（经典坑：BE 未重编译 → 老行为）。修复后无权限请求应得到 401/403 而非 404。

## 9. MCP 导入 404 修复后：`IScopedClientFactory` 未注册（13:10）
- 用户 VS 重编译重启后，404 已消失（请求进入 `McpController.ImportOpenApi`，且 FusionCache 日志显示 `Auth:Permissions:*` 权限校验通过 → `RequirePermissionActionFilter` 生效）。

- **MCP 工具返回 code:600"登录过期"**：是上游 OA（192.168.1.64:5201，ZRAdmin 风格外壳 msg/extras）的业务响应，经网关透传；原因是 MCP Server 的 AuthToken 为空或过期（HttpToolExecutor 仅在 AuthToken 非空时加 Bearer 头，HTTP 200 业务错不会包装 API Error）。同时证明 SSE 修复后全链路已通。待办：MCP Server 支持自动登录换 token。
- **MCPDemo AI 模式 arguments 空串崩溃修复**：模型把 function calling 的 arguments 返回成空字符串 ""（无参工具常见，尤其中转站），原兜底只处理 null 漏了 ""，导致 PrettyJson("")/JsonDocument.Parse("") 抛 "input does not contain any JSON tokens"。改为：arguments 三种形态（string/object|array/missing）统一兜底为 {}；PrettyJson 空串直接原样返回。已人工复查。
- **MCPDemo AI 模式空 body 崩溃（续）**：arguments 空串修复后仍报 "input does not contain any JSON tokens"，定位到是 OpenAiChatClient.ChatAsync 里 `JsonDocument.Parse(空响应体)` —— 中转站返回 200 但 body 为空。改为：Chat 客户端用独立 HttpClient（不复用 SSE 长连接 client）+ 显式 `stream:false` + 空 body 中文诊断。绝大多数"流式中转站刷 200 头、body 边生成边推"场景可借此修复。

- **MCPDemo AI 模式 OpenAI 400 schema 校验修复**：agnes 中转站返回 400 "Tool N function has invalid 'parameters' schema: None is not of type 'string'" —— 根因是 MCP tools/list 的 inputSchema 里某属性（如 id）的 description 为 null（Python 的 None），OpenAI 严格校验要求 description 必须是 string。新增 `CleanJsonSchema` 递归删除所有 null/非字符串的 description/title；`MakeOpenAiParameters` 兜底无参/空 schema 保证根 type=object。ag: 中转站 400 空 body 修复后首次进模型即报 schema 错。
