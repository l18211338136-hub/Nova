## 用户名（Username）登录失败（根因修复）
用户反馈：用 Username（如 `root`）走密码登录失败，用邮箱登录正常。

- **根因**：`GlobalUserTenantMapping` 表的 `Account` 字段只存了**邮箱**。所有写入映射的地方（`CreateUserCommandHandler`、`IdentityDbInitializer` 的 root/普通租户两个 seed 点）都只 `Account = user.Email`。而 `LoginCommandHandler` 用 `m.Account == request.Account` 查找映射——输入用户名 `root` 时，映射表里只有 `root@example.com`，匹配不到 → 抛"账号或密码错误"。
- **修复（双记录方案，无需改实体 / 无需新增迁移）**：注册和 seed 时**同时写入邮箱映射和用户名字段两条记录**，登录查找逻辑零改动即可匹配用户名或邮箱。关键点：seed 逻辑从"仅当都不存在才插入"改为"分别检查 email / username 是否存在，缺哪条补哪条"，这样**存量用户**（如 root 只有 Email 映射）重启后会自动补全 UserName 映射。
  - `CreateUserCommandHandler.cs`：用 `AnyAsync` 分别确认 email / userName 映射，缺则 Add；补 `using Microsoft.EntityFrameworkCore;`（否则 `AnyAsync` 会误解析到 `System.Linq.Async` 导致 CS0411）。
  - `IdentityDbInitializer.cs`：root 与普通租户 seed 点各补一条 UserName 映射（`user.UserName`）。
- **注意**：普通租户 `User.Create(adminEmail, adminEmail)` 使 UserName == Email，故 Username 映射与 Email 映射相同，由 `AnyAsync` 守卫避免重复；真正受益的是 UserName≠Email 的用户（如 root）。编译通过（0 错误）。
- **用户需重启后端**使映射补全生效；root 用户重启后可用 `root` 或 `root@example.com` 登录。

## 日期筛选器增强：操作符选择 + UTC 修复

1. 选日期后报错 `Cannot write DateTime with Kind=Local to PostgreSQL type 'timestamp with time zone'`（Npgsql 只接受 UTC）

**根因**：
- `DateRangePicker` 的 `new Date(ISO)` 创建本地时间，`.toISOString()` 虽输出 UTC 字符串但后端 OData 解析可能创建 Kind=Local 的 DateTime
- 原设计只有范围模式（ge+le），无法表达 gt/lt/ge-only/le-only

**改动（4 个文件）**：
- **`date-range-picker.tsx`**：完全重写。
  - 新增 `DateOp` 类型（`between|after|before|onOrAfter|onOrBefore`）+ `DateFilterValue`（`{op, from?, to?}`）。
  - UI 上方增加操作符下拉选择（5 个选项），下方是日期按钮 + 日历弹窗。
  - `between` 模式用 `Calendar mode='range'`（双月视图），其余模式用 `mode='single'`（避免 TS 条件类型 union 报错）。
  - **UTC 修复**：新增 `toUtcIso()` 用 `Date.UTC()` 构造确保 UTC kind；输出 ISO 字符串末尾带 `Z`。
  - 显示文本根据 op 动态变化：范围显示 "from – to"，单边显示 "≥ date" 或 "date <" 等。
- **`column-filter.tsx`**：date 分支适配新 `DateFilterValue` 对象格式；移除未使用 `useMemo` import。
- **`audit-table.tsx`**：occurredOn 列配置从 `type:'array'`（逗号分隔）改为 `type:'string'`（JSON 序列化 `{op,from,to}`），自定义 serialize=JSON.stringify、deserialize=JSON.parse。
- **`odata.ts`**：`buildODataFilter` 新增 `isDateFilterObj` 判定分支，按 op 映射到 OData 操作符（between→ge+le, onOrAfter→ge, after→gt, onOrBefore→le, before→lt）；`formatODataValue` 加强 ISO 字符串检测，无 Z 后缀的自动补 Z 确保 UTC。
- **i18n**：补 Between/On or after/On or after/After/Before 及 ≥/≤/>/< 符号 key（中英文）。

## 日期筛选"选不上"修复（操作符移入日历弹窗后的回归）
用户反馈：把操作符条从外部下拉框移到日历弹窗内部顶部后，日期点选不上。

- **根因（经典双 Z 错误）**：`toUtcIso()` 输出已是带 `Z` 的 UTC ISO（如 `2026-08-01T00:00:00Z`），但 `DateRangePicker` 解析时又拼了 `+ 'Z'` → `2026-08-01T00:00:00ZZ` → `new Date()` 解析成 **Invalid Date**。日历 `selected` 为非法日期，高亮匹配失败、`format()` 显示异常，表现为点选无效。
- **修复**：`date-range-picker.tsx` 的 `fromDate`/`toDate` 改为 `new Date(value.from)` / `new Date(value.to)`（直接解析已带 Z 的 UTC 字符串，不再重复拼 Z）。类型检查通过。
- **经验**：凡是"存的是 UTC ISO(带Z)、取时又拼 'Z'"的日期控件都会踩 Invalid Date 坑；`toUtcIso` 既已带 Z，读取端一律不要再加 `Z`。

## 审计日期筛选后端报错（Kind=Local）— 根因与底层修复
用户复现：审计日志选时间筛选后，后端抛 `Cannot write DateTime with Kind=Local to PostgreSQL type 'timestamp with time zone', only UTC is supported`，发生于 `IdentityODataEndpoints.cs:190`（`filteredQuery.LongCountAsync`）。

- **根因（实测确认）**：`Microsoft.AspNetCore.OData` 9.5 解析带时区偏移的日期字面量（如 `OccurredOn ge 2026-08-01T00:00:00Z`）时，先把 `DateTimeOffset` 转成 **本地墙钟 DateTime（`Kind=Local`）**，但完整保留了瞬时时刻（instant）。即输入 `…Z`（UTC）会被转成服务器本地时间（如中国 +8 → `08:00` Kind=Local）。Npgsql 对 `timestamp with time zone` 列只接受 `Kind=Utc` → 报错。
- **实测方法**：建了 `D:/tmp/odatarepro` 控制台（引用 OData 9.5.0），`ApplyTo` 后反射 `TypedLinqParameterContainer<DateTime>.TypedProperty`，确认 `2026-08-01T00:00:00Z` → `2026-08-01T08:00:00 Kind=Local`，`+05:30` → `02:30 Local`，`+08:00` → `00:00 Local`（均与"保留 UTC 瞬时 + 转本地墙钟"一致）。
- **修复（通用、不改 DTO）**：新增 `UtcDateTimeParameterInterceptor : DbCommandInterceptor`（`src/Framework/Nova.Framework.Persistence/Interceptors/`），在 `ReaderExecuting/NonQueryExecuting/ScalarExecuting`（含 Async）里遍历参数：对 `NpgsqlParameter` 且 `Value is DateTime` 且 `Kind != Utc`、**且列类型为 `TimestampTz` 或 `Unknown`（Npgsql 默认按 timestamptz）** 的参数，执行 `dt.Kind == Local ? dt.ToUniversalTime() : DateTime.SpecifyKind(dt, Utc)`。因为 OData 保留的是 UTC 瞬时，`ToUniversalTime()` 可精确还原 UTC（与服务器本地时区无关，前后两次转换用同一时区恒等）。`timestamp without time zone` 列（`NpgsqlDbType.Timestamp`）不处理，避免改本地墙钟语义。拦截器幂等，可安全复用。
  - 新增 `Npgsql` 包引用（CPM `Directory.Packages.props` 补 `Npgsql 10.0.0`，与已解析版本一致）；`Nova.Framework.Persistence.csproj` 加 `PackageReference Include="Npgsql"`。
  - 注册：`IdentityModule.cs`（IdentityDbContext）与 `MultiTenancyExtensions.cs`（NovaTenantDbContext）均 `services.AddSingleton<UtcDateTimeParameterInterceptor>()` 并在 `AddDbContext` lambda 内 `options.AddInterceptors(sp.GetRequiredService<UtcDateTimeParameterInterceptor>())`。`MultiTenancy` 项目补 `ProjectReference` 指向 `Nova.Framework.Persistence`（否则 using 找不到 `Nova.Framework.Persistence.Interceptors`）。
- **注意**：此为底层通用修复，所有走 OData 的日期筛选（及任何写入 timestamptz 的本地 DateTime）都受益，不仅限于审计。编译 0 错误（仅 EF 拦截器异步方法返回类型可空性 CS8609 警告，无害、拦截照常触发）。

   - `number-range-picker.tsx`：操作符 label key 改为数字专用：`Number between`/`Number at least`/`Number at most`/`Number more than`/`Number less than`。
   - 两份 `translation.json` 新增对应 key（zh："介于两值之间"/"大于或等于"/"小于或等于"/"大于"/"小于"；en："Between values"/"At least"/"At most"/"More than"/"Less than"）。

## 用户/角色/菜单/租户列表全部字段可过滤
用户要求截图里的四个管理列表（用户管理、角色管理、菜单管理、租户管理）的每个字段都能过滤。

- **已支持的过滤类型**：text / boolean / date / number（由 `column-filter.tsx` 统一渲染）。
- **补全的 text 过滤列**：
  - 用户：`userName`、`email`、`phoneNumber`
  - 角色：`name`、`displayName`
  - 菜单：`name`、`path`、`component`（`sort` 已 number，`isEnabled` 已 boolean）
  - 租户：`id`、`name`、`identifier`、`adminEmail`（`isActive` 已 boolean，`validUpto` 已 date）
- **实现**：在对应 `*-columns.tsx` 的 `meta` 里加 `filterType: 'text'`。用户/角色/租户走 OData 后端过滤（`odata.ts` 会生成 `contains(Field,'value')`）；菜单走客户端过滤（`getFilteredRowModel` + 默认 `includesString`）。
- **注意**：租户 `id` 是 GUID，OData `contains` 对 GUID 字段可能后端报错；若出现，需改成精确匹配 `eq`。先按用户"每个字段都能过滤"加上，有运行时问题再调。
- **验证**：`pnpm check:i18n` 通过；`tsc -b --noEmit --force` 本次改动列文件无新增错误。
