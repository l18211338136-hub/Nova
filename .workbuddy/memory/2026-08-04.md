## 审计日志菜单重复 + 显示为「系统跟随」
用户截图反馈：侧边栏同时出现「系统设置 > 审计日志」和「系统跟随 > 审计日志」，且父节点不是「日志管理」而是「系统跟随」。

- **根因**：`IdentityDbInitializer.SeedMenusAsync` 按 `Path` 做全局判重，但**不更新已有菜单的名称、排序、父级**。数据库里已经存在：
  - `Path=/logs` 的父节点，实际名称为「系统跟随」；
  - `Path=/audit` 的审计日志，仍挂在「系统设置」下。
  种子把新的审计日志子节点匹配到已有 `/audit` 后未迁移父级，同时 `/logs` 被复用为「系统跟随」，导致重复和名称错误。
- **改动**：`src/Modules/Identity/Nova.Modules.Identity.Infrastructure/IdentityDbInitializer.cs`
  - 对于已存在的根菜单，调用 `Update(...)` 同步名称/图标/排序/组件。
  - 对于已存在的子菜单，调用 `Update(...)` 同步上述属性，并**强制把父级修正为当前根菜单**（支持菜单迁移）。
  - 这样 `seed_menus.json` 成为权威来源，后续改结构无需再清库。
- **清理数据**：需要执行 SQL 删除旧的 `/audit` 和 `/logs` 菜单及其关联的 Menu claim，让种子重新创建正确的「日志管理 > 审计日志」结构。
  ```sql
  BEGIN;
  DELETE FROM identity."RoleClaims" 
  WHERE "ClaimType" = 'Menu' 
    AND "ClaimValue" IN (SELECT "Id"::text FROM identity."Menus" WHERE "Path" IN ('/audit', '/logs'));
  DELETE FROM identity."Menus" WHERE "Path" IN ('/audit', '/logs');
  COMMIT;
  ```
- **生效条件**：执行 SQL 后重启后端，种子会自动重建菜单并重新给 Root/Admin 分配 Menu claim。

## 修复：重启项目数据被重置（菜单种子覆盖）
用户反馈：每次重启后端，菜单等数据被重置。

- **根因**：`src/Modules/Identity/Nova.Modules.Identity.Infrastructure/IdentityDbInitializer.cs` 的 `SeedMenusAsync` 在每次启动都会对已存在的菜单调用 `rootMenu.Update(...)` / `childMenu.Update(...)`，把名称/父级/排序/图标**强制同步回 `seed_menus.json`**，覆盖用户在界面做的修改。用户/角色/权限种子都是"不存在才创建"未受影响；迁移 `DropTable` 全在 `Down()`（回滚路径），正常启动不触发。
- **修复**：把 `SeedMenusAsync` 改为**幂等只增不覆盖**——按 `Path` 判重，仅当菜单不存在时才 `Create`；已存在菜单不再被 JSON 覆盖（保留运行时改名/改父级/改排序）。角色菜单访问 claim 分配逻辑不变。
- **顺带修复一个真 bug**：`DeleteMenuCommandHandler.cs` 原只 `_db.Menus.Update(menu)` 而未置 `IsDeleted`，导致"删除菜单"是空操作（界面删菜单也删不掉）。改为 `_db.Menus.Remove(menu)`，由 `AuditableEntitySaveChangesInterceptor` 拦截转为软删除（`IsDeleted=true`，全局查询过滤器自动排除）。
- **验证（端到端）**：
  - 用 Python(UTF-8) 把 `审计日志` 改名为 `AuditRenamed_X` → 重启后端 → 名称**仍为 `AuditRenamed_X`**（证明不再被种子覆盖）；运行时新增的临时菜单 `/x2` 重启后仍在。
  - 改回 `审计日志`、删除 `/x2` 后，菜单列表恢复干净：`/users /roles /tenants /menus /logs /system /audit`。
  - 重新编译 0 error（workaround；需先杀占用 `artifacts-live` dll 的旧进程避免 MSB3021）。
- **注意**：现在若想用 `seed_menus.json` 作为权威来源一次性重置菜单结构，需手动清 `Menus` 表或删对应行再重启；常规开发迭代以界面改动为准。后端当前运行于 `http://localhost:5000`（Development，新编译）。
- **curl 中文坑**：Git Bash 下 `curl -d '{"name":"中文"}'` 会因 shell 编码把中文破坏为无效 JSON（反序列化抛异常→命令回退成全 null→报 "Value cannot be null"）。验证带中文的请求请用 PowerShell `Invoke-RestMethod` 或 Python `urllib`（`ensure_ascii=False`+utf-8），不要用带中文的内联 curl。
