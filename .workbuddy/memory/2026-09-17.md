### 修复：大 Swagger(>30MB) 解析报 500
- 现象：`POST /api/mcp/parse` 传大 JSON（企业级 API 文档常 >30MB）时 `BadHttpRequestException: Request body too large. The max request body size is 30000000 bytes`，堆栈落在 `GlobalAuditLoggingMiddleware.ReadRequestBodyAsync`（审计中间件在 MVC 之前读请求体时触发 Kestrel 默认 30MB 上限）。
- 修复：`Program.cs` 在 `app.UseMiddleware<GlobalAuditLoggingMiddleware>()` **之前**插入路由级中间件，仅对 `/api/mcp/parse` 设 `context.Features.Get<IHttpMaxRequestBodySizeFeature>().MaxRequestBodySize = 100MB`。
- **坑**：不能只给 Controller 加 `[RequestSizeLimit]`——审计中间件在过滤器之前读体，属性来不及生效；必须在管线更前置处改 `IHttpMaxRequestBodySizeFeature`。
- 审计中间件本身已把请求/响应体截断到 65536 字符再写审计（GlobalAuditLoggingMiddleware.cs:241/273），故大请求不会撑爆审计存储。
- 验证：36.4MB Swagger → HTTP 200 解析出 55606 接口；其余接口仍保持默认 30MB。
